# 3x-ui روی Railway — اینباند خودکار «ای اچ بی | AHB PANEL» + ساب‌لینک زنده

## این بسته چیکار می‌کنه؟

- 3x-ui نسخه‌ی `v2.9.4` رو با nginx پشت یک پورت واحد (پورت Railway) بالا میاره.
- همون لحظه‌ی اول بوت، به‌صورت خودکار (بدون دخالت شما) یک اینباند VLESS+WebSocket با نام **ای اچ بی | AHB PANEL** می‌سازه.
- یک UUID و subId ثابت براش تولید می‌کنه که سابلینکش همیشه کار کنه و بعد از ری‌استارت هم عوض نشه.
- یک «حلقه‌ی نگهبان» هر ۶۰ ثانیه چک می‌کنه این اینباند هنوز هست یا نه؛ اگه از پنل پاکش کرده باشید، خودکار دوباره می‌سازدش.

## ⚠️ یک نکته‌ی مهم و صادقانه درباره‌ی «غیرقابل پاک کردن»

3x-ui به‌صورت داخلی هیچ قابلیتی برای «قفل کردن» یا جلوگیری واقعی از پاک شدن یک اینباند نداره — دکمه‌ی Delete همیشه در پنل کار می‌کنه.
چیزی که این بسته می‌ده، نزدیک‌ترین جایگزین عملیه: یک watchdog که حداکثر تا ۶۰ ثانیه بعد از پاک شدن، اینباند رو با همون UUID/subId قبلی دوباره می‌سازه. یعنی عملاً همیشه هست، ولی یه لحظه امکان پاک شدنش از داخل پنل وجود داره تا watchdog دوباره بسازدش.

## مراحل دیپلوی

1. سه فایل `Dockerfile`, `nginx.conf.template`, `start.sh`, `bootstrap-inbound.sh` رو داخل یک ریپازیتوری گیت‌هاب بریزید.
2. در Railway: **New Project → Deploy from GitHub repo**.
3. بعد از دیپلوی، برید **Settings → Networking → Generate Domain**.
4. (اختیاری ولی پیشنهادی) در **Variables** این‌ها رو تنظیم کنید تا هر ری‌دیپلوی، دیتای قبلی رو حفظ کنه:
   - `PANEL_USER`, `PANEL_PASS` → یوزر/پس پنل (پیش‌فرض admin / ChangeMe123! — حتماً عوضش کنید)
   - `CLIENT_UUID`, `SUBID` → اگه می‌خواید لینک کلاینت هیچ‌وقت عوض نشه، خودتون یه UUID و یه رشته‌ی رندوم ثابت بدید
   - در صورت تمایل یک **Volume** روی مسیر `/etc/x-ui-bootstrap` و `/etc/x-ui` وصل کنید تا دیتابیس و UUID حتی بین ری‌دیپلوی‌های کامل هم حفظ بشه (پیش‌فرض Railway حافظه‌ی کانتینر رو در هر ری‌دیپلوی از صفر می‌سازه)

## بعد از بالا اومدن

- پنل: `https://دامنه‌شما.up.railway.app/managepanel/` با یوزر/پسی که در `PANEL_USER`/`PANEL_PASS` دادید
- وقتی وارد پنل بشید، اینباند «ای اچ بی |  AHB PANEL» از قبل آماده‌ست، لازم نیست چیزی بسازید
- سابلینک: `https://دامنه‌شما.up.railway.app/subpath/<SUBID>` (مقدار SUBID رو از تب Inbounds → روی کلاینت → دکمه Sub می‌تونید کپی کنید)
- برای اتصال کلاینت‌ها: Host = دامنه Railway، پورت = 443، TLS = روشن، Network = ws، Path = `/wspath`

## چرا TLS رو خاموش گذاشتیم داخل Xray؟

چون از بیرون، Railway خودش گواهی TLS رو در لبه (edge) هندل می‌کنه و ترافیک رو به‌صورت HTTP ساده به کانتینر شما می‌فرسته. پس داخل Xray نیازی به TLS نیست؛ کلاینت باید TLS رو روشن بذاره چون از دید اون، اتصال به دامنه‌ی Railway از پشت HTTPS انجام می‌شه.

به همین دلیل پروتکل‌هایی مثل REALITY که به اتصال مستقیم TCP نیاز دارن، پشت این معماری (هر PaaS مبتنی بر HTTP مثل Railway) کار نمی‌کنن.
